# Чеклист дизайнера

Используйте этот короткий чеклист перед передачей файла Figma в разработку. Если пункт требует отдельного решения, откройте подробное правило, а не пытайтесь сразу прочитать всю спецификацию.

## Сначала выберите область

Передавайте:

- целую страницу с подготовленными ширинами;
- или одну явно отмеченную новую секцию внутри существующего продукта.

Не добавляйте метаданные страницы в существующий продукт только ради проверки одной секции. Для этого случая см. [руководство по внедрению в команду](19-vnedrenie-v-komandu.md).

## Страница и ширины

- [ ] По корню понятны страница, настоящий маршрут, ширина и состояние.
- [ ] Подготовленные корни описывают одну страницу и сохраняют один смысл.
- [ ] Один логический элемент сохраняет одно имя на разных ширинах.

Подробнее см. в разделе [адаптивов](03-adaptivy-i-breakpointy.md).

## Имена и связи

- [ ] Важные слои используют короткие английские имена в `kebab-case`.
- [ ] В именах нет суффиксов устройства или ширины.
- [ ] Связанные слои соединены осмысленным родителем, а не только визуальной близостью.

Подробнее см. в разделах [имён слоёв](02-imena-sloev-i-identichnost.md) и [правил подготовки макета](01-pravila-dizajna.md).

## Ссылки, действия и состояния

- [ ] У каждой ссылки есть `[href]` или осознанно записанный открытый вопрос.
- [ ] У каждого изменения интерфейса есть `[action]` и существующая цель.
- [ ] Важные обычное, загружаемое, пустое, ошибочное и успешное состояния показаны или описаны.

Подробнее см. в разделах [действий](05-interaktivnost-i-celi.md) и [реакций состояний](22-sostoyaniya-i-reakcii.md).

## Контент и компоненты

- [ ] Текст, цены, изображения и списки выдерживают реальные данные и локализацию.
- [ ] Контент, декор и экспортируемые ресурсы различимы.
- [ ] Компоненты взяты из правильной библиотеки и остаются редактируемыми там, где нужно.

Подробнее см. в разделах [компонентов](14-komponenty-i-ui-kit.md) и [контента и переполнения](07-vysoty-i-overflow.md).

## Проверка передачи

- [ ] Человек, который не готовил файл, может без звонка найти страницу, ширины, действия, цели и редактируемые ресурсы.

Если ответ остался в переписке, добавьте его в файл или запишите как открытый вопрос с владельцем. Затем запустите [проверку страницы в Figma](https://www.figma.com/community/plugin/1654485530503673254/bridge).

## Для строгого аудита

Открывайте [полную проверку](08-preflight-checklist.md), только если команде нужен подробный аудит данных, доступности, движения, реализации и выпуска.
