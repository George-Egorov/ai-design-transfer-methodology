# Терминология BRIDGE

Этот словарь задаёт канонические понятия BRIDGE 0.9. Используйте эти значения в макете, структурированном контракте, заметках реализации, проверке качества и отклонениях.

## Правило употребления

Пояснения для людей можно переводить. Машиночитаемые теги слоёв, поля JSON, идентификаторы правил, значения перечислений и стабильные ссылки сохраняют каноническую английскую форму. Привычное значение слова не отменяет определения BRIDGE ниже.

## Шесть принципов

| Каноническое название | В русском тексте | Значение в BRIDGE |
| --- | --- | --- |
| **Breakpoints** | адаптивные контексты | Подготовленные контрольные ширины вместе с правилами для окна, контейнера, плавных и внутренних размеров, направления письма и возможностей платформы. Это не просто набор скриншотов и не автоматически вычисленные медиавыражения CSS. |
| **Roles** | роли | Логическое назначение элемента, отображения данных, действия или владельца. Сначала оно определяется нативными метаданными источника, а при необходимости — явным намерением BRIDGE. |
| **Identity** | идентичность | Трассируемое сопоставление роли, шаблона, экземпляра макета, рабочих данных и целевой реализации, а не один перегруженный идентификатор. |
| **Dependencies** | зависимости | Данные, действия, цели, состояния, эффекты фокуса/истории, возможности и наследуемые контракты, необходимые для результата. |
| **Geometry** | геометрия | Воспроизводимые точные, ступенчатые, плавные, внутренние, пространственные и временные свойства: границы, интервалы, параметры текста, диапазоны и дорожки движения. |
| **Exceptions** | исключения | Намеренные исключения из правила источника или контракта с областью, причиной, влиянием, компенсацией, владельцем, свидетельством и пересмотром. Адаптивное преобразование или отклонение реализации не становится исключением автоматически. |

Первые буквы английских названий образуют BRIDGE. В обычном русском объяснении используйте русские понятия, а канонические названия сохраняйте там, где важна расшифровка.

## Источник и поверхности контракта

| Понятие | Значение |
| --- | --- |
| **Свидетельство макета/источника** | Версионированный файл, страница, узел, компонент, нативные метаданные, пример данных, прототип, аннотация или ресурс, показывающие авторское намерение. Figma — возможный, но не обязательный источник методологии. |
| **Корень** | Верхний объект источника для страницы, представления, адаптивного контекста или самостоятельной секции. |
| **Стабильное имя слоя** | Видимая человеку английская опорная точка в `kebab-case`, которая не кодирует ширину окна, тип устройства или позицию рабочей записи. |
| **Короткий тег слоя** | Каноническая пометка в квадратных скобках, например `[page=catalog]`, `[href=/catalog]` или `[item=product]`, только для краткого намерения, которое должно быть видно в дереве слоёв. |
| **Структурированные метаданные `bridge`** | Именованные данные для связей, которые не помещаются в имя: идентичности, отображения данных, адаптивные преобразования, реакции, движение, доступность, возможности, жизненный цикл, вопросы и исключения. |
| **Контракт BRIDGE** | Версионированное и независимое от платформы сочетание свидетельств источника, коротких опорных тегов, структурированных метаданных, требований и критериев приёмки, передаваемое в реализацию и проверку. |
| **Обязательная оболочка** | Полный документ с корнем `bridge`, поддерживаемыми версиями и полями `source`, `context`, `identity`; внутри размещаются применимые модули. |
| **Фрагмент модуля** | Неполная выдержка вроде `{ "bridge": { "data": … } }`, объясняющая один модуль. Перед обменом или проверкой полного контракта её нужно вставить в обязательную оболочку. |
| **Требование** | Стабильное утверждение о поведении или качестве с точной областью и проверяемым результатом. |
| **Критерий приёмки** | Наблюдаемое условие, определяющее результат требования в объявленном контексте. |
| **Свидетельство** | Доступный по ссылке артефакт источника, контракта, реализации, теста, измерения или ревью, подтверждающий результат требования. |
| **Ревизия** | Неизменяемая версия источника, контракта, реализации или свидетельства, закреплённая в решении жизненного цикла. |

## Идентичность и ссылки

| Понятие | Значение |
| --- | --- |
| **`bridgeKey`** | Стабильная ссылка контракта на один логический элемент макета. Она связывает записи, но не заменяет пять измерений идентичности. |
| **Роль** | Задача элемента: например, навигация, элемент данных товара, статус или поле формы. |
| **Шаблон** | Переиспользуемое определение компонента или секции, владеющее структурой и наследуемым поведением; при необходимости задаётся через `templateKey`. |
| **Экземпляр макета** | Один подготовленный экземпляр и его узлы в объявленных контекстах; задаётся через `designInstanceKey`. |
| **Рабочие данные** | Коллекция, стабильное правило ключа записи и необязательная привязка примера; `runtimeDataKey` никогда не означает позицию массива. |
| **Целевая реализация** | Компонент, нативный элемент управления, представление, маршрут, сущность или адрес, реализующий контракт на платформе. |
| **Цель взаимодействия** | Модальное окно, состояние, форма, маршрут или элемент, к которому ведёт реакция по стабильной ссылке BRIDGE. Это не то же самое, что сопоставление целевой реализации. |
| **Значение `[item=…]`** | Повторяемая роль или тип элемента, например `[item=product]`. Соседние элементы намеренно могут иметь одинаковое значение. Уникальность подготовленного и рабочего экземпляра задают стабильное имя слоя/`bridgeKey`, `designInstance` и `runtimeData`, а не `[item]`. |
| **Ключ примера** | Стабильная привязка подготовленных данных для воспроизведения сценария. Она может обозначать пример дубового стула, но не становится ключом рабочей записи. |

## Адаптивность и вариативность

| Понятие | Значение |
| --- | --- |
| **Адаптивный контекст** | Именованный контекст раскладки с объявленным источником условий — окном или контейнером — и применимыми осями вариативности. |
| **Контрольная ширина** | Подготовленная ширина корня с `[bp=…]`. Это авторская опорная точка, а не автоматически граница CSS. |
| **Одно дерево по умолчанию** | Правило, по которому логические элементы, смысл, действия, связи данных и семантика доступности остаются равнозначными между контекстами, если не объявлено преобразование. |
| **Структурное преобразование** | Объявленное сопоставление `fromContext` и `toContext` при изменении топологии или модели представления. Оно задаёт условие, исходные и целевые элементы, сохраняемый смысл, порядок, перенос состояния, историю, обратный ход и запасной вариант. Это не исключение. |
| **Ступенчатое поведение** | Дискретное правило, меняющееся при явном условии. |
| **Плавное поведение** | Значение, непрерывно вычисляемое между заданными минимумом, предпочтением и максимумом. |
| **Внутреннее поведение** | Раскладка, определяемая содержимым, доступным местом или нативным примитивом платформы, а не фиксированной шириной. |
| **Ось вариативности** | Пользовательское, контентное, средовое или продуктовое измерение: язык/регион, тема, направление, режим письма, роль, состояние данных, ввод, предпочтение движения или возможность. |
| **Направление и режим письма** | Объявленный контекст `ltr`/`rtl` и горизонтального/вертикального письма с логическим порядком/свойствами и решениями о зеркальности. |
| **Двунаправленное содержимое** | Смешанный текст, например арабская подпись с латинским идентификатором, числом, датой или SKU. Для него задают изоляцию, порядок, формат, оси диаграмм, порядок клавиатуры и тестовые примеры. |

## Содержимое, данные и визуализация

| Понятие | Значение |
| --- | --- |
| **Подготовленное содержимое** | Текст или медиа, утверждённое значение которых входит в контракт макета/источника. |
| **Рабочие данные** | Значения, поступающие из сервиса, CMS, ввода пользователя, устройства или среды после реализации. |
| **Отображение данных** | Таблица, сетка, список, набор карточек, диаграмма, карта, метрика или другое представление, отвечающее на объявленный вопрос по структурированным данным. |
| **Схема данных** | Типы полей, стабильные ключи, возможность пустого значения, связи и количество записей, ожидаемые отображением или реакцией. |
| **Пример данных** | Версионированные данные для обычного, граничного, ошибочного, локализованного, направленного, приватного или доступного сценария. |
| **Происхождение данных** | Набор/источник, ответственный владелец, агрегация, обновление, ограничения, приватность и время последнего обновления, необходимые для понимания значений. |
| **Состояние данных** | Различимое условие: `loading`, `empty`, `partial`, `stale`, `error`, `offline` или `unauthorized`, с обратной связью и восстановлением, где применимо. |
| **Смысл формата** | Язык/регион, единица, валюта, часовой пояс, точность, округление, знак, диапазон и правила для отсутствующего/нулевого/оценочного значения, влияющие на смысл. |
| **Доступный эквивалент** | Таблица, список, сводка, подробное представление или загрузка, открывающие важные значения и вывод сложной графики без зависимости только от цвета, наведения, canvas или анимации. |

## Взаимодействия и состояния

| Понятие | Значение |
| --- | --- |
| **Реакция** | Версионированный ответ на событие: предусловия, смена состояния, эффекты, исходы, фокус, объявления и история. |
| **Машина состояний** | Ограниченная модель достижимых состояний и детерминированных переходов компонента, формы, сценария или страницы. |
| **Представление** | Состояние уровня страницы или данных: обычное, загрузка, пустота или ошибка. Оно не заменяет полную машину состояний. |
| **Событие** | Действие пользователя, системы, данных, времени или истории, запрашивающее переход. |
| **Условие перехода** | Проверка, разрешающая, отклоняющая или перенаправляющая переход. |
| **Эффект** | Работа перехода: запрос, запись в хранилище, перемещение фокуса, объявление или навигация. |
| **Исход** | Именованный успех, пустота, неверный ввод, ошибка, таймаут, отмена или конфликт и следующее состояние. |
| **Правила асинхронности** | Поведение ожидания, конкурентности, повторных событий, отмены, таймаута, устаревшего ответа, повтора, отката и восстановления. |
| **Контракт фокуса** | Начальный фокус, порядок, перемещение, восстановление, видимость и объявления при переходе. |
| **Контракт истории** | Путь, параметры, якорь и хранилище адреса, добавление/замена записи, Назад/Вперёд, обновление, глубокая ссылка, прокрутка и восстановление фокуса. |

## Движение и длинная прокрутка

| Понятие | Значение |
| --- | --- |
| **Последовательность движения** | Набор осмысленных стабильных состояний, соединённых объявленными правилами времени или прогресса. |
| **Источник прогресса** | Время, прокрутка документа/контейнера, перетаскивание, время медиа или переход состояния, управляющие прогрессом. |
| **Временная шкала/дорожка** | Упорядоченные диапазоны и изменения свойств внутри последовательности. |
| **Сцена** | Осмысленное стабильное состояние или интервал длинной последовательности. |
| **Закреплённая область** | Содержимое, удерживаемое в объявленных границах контейнера при заданных месте в потоке, владельце прокрутки, фокусе и запасном варианте. |
| **Правила обратного хода и повторного входа** | Поведение при движении назад, возврате пользователя, быстром вводе или прерывании последовательности. |
| **Вариант с уменьшенным движением** | Статичное или сокращённое поведение, сохраняющее задачу, содержимое, состояние и фокус без проблемного перемещения, параллакса или цикла. |
| **Запасной вариант движения** | Семантический результат при неподдерживаемом источнике прогресса или возможности платформы; завершение не зависит только от события конца анимации. |

## Доступность

| Понятие | Значение |
| --- | --- |
| **Профиль доступности** | Целевой стандарт, версия и уровень вместе с требованиями к семантике, вводу, графике, медиа, движению, адаптивности и проверке. Для веба BRIDGE 0.9 по умолчанию использует WCAG 2.2 уровня AA. |
| **Цель соответствия** | Стандарт, которому стремится соответствовать полная реализация. Это не заявление о соответствии макета, отдельного компонента, автоматической оценки или незавершённого процесса. |
| **Доступное название/описание** | Программно доступная метка и пояснение элемента; видимый текст, совпадение названия и контекст повторяющихся элементов остаются согласованными. |
| **Порядок чтения** | Семантический порядок содержимого и связей, независимый от чисто визуального расположения. |
| **Порядок фокуса** | Последовательность клавиатуры и вспомогательных технологий по интерактивному содержимому. Она остаётся логичной и видимой и отличается от чтения только намеренно. |
| **Живой статус** | Значимое динамическое обновление, объявляемое без неожиданного перемещения фокуса. |
| **Перестроение** | Сохранение содержимого и функций при требуемом масштабе и эквивалентной узкой ширине без неоправданной двумерной прокрутки. |
| **Размер цели** | Интерактивная область указателя с учётом применимых исключений WCAG и более строгих продуктовых/платформенных требований. |

## Возможности и производительность

| Понятие | Значение |
| --- | --- |
| **Профиль цели** | Именованный контекст платформы/среды и возможностей ввода, вывода, раскладки, медиа, сети, хранилища, памяти и питания. |
| **Возможность** | Функция платформы, на которую контракт опирается только при объявленной поддержке или проверенной альтернативе. |
| **Существенный опыт** | Содержимое, задача, смысл медиа и результат, которые сохраняются при деградации, даже когда точная графика или продвинутый эффект невозможны. |
| **Запасной вариант** | Запланированная безопасная альтернатива для неподдерживаемого, нерешённого, ошибочного или ограниченного условия. Она не становится отклонением автоматически. |
| **Деградация** | Намеренный переход к сокращённому, но пригодному опыту при низкой скорости, offline, экономии трафика/энергии, нехватке памяти, отсутствии API/кодека и похожих условиях. |
| **Бюджет производительности** | Измеримый предел с метрикой, единицей, владельцем, целевым окружением, точкой измерения и свидетельством. |
| **Кадрирование по смыслу** | Обрезка, фокусная/безопасная область, пропорции, разрешение, формат, качество, постер/превью и выбор источника, сохраняющие смысл медиа. |
| **Порог виртуализации** | Объём данных, после которого меняется стратегия отрисовки окна, но идентичность, порядок, фокус, выбор и доступность остаются корректными. |

## Жизненный цикл и управление

| Понятие | Значение |
| --- | --- |
| **Жизненный цикл** | Трассируемая цепочка от макета к контракту, реализации, проверке, выпуску, эксплуатации и обратной связи. |
| **Условие этапа** | Решение этапа макета, контракта, реализации, проверки или выпуска с областью, ревизиями, свидетельствами, владельцами и явным результатом. |
| **Передача макета** | Доставка принятого источника и контракта в реализацию; это один переход жизненного цикла, а не конец ответственности. |
| **Готовность по BRIDGE** | Достаточная явность для перехода затронутой области без выдумывания поведения и неучтённых неизвестных. |
| **Открытый вопрос** | Известное решение со статусом `unknown`, `unsupported` или `TBD`: стабильный идентификатор, точная область, владелец, блокирующий статус, срок/этап пересмотра, безопасный запасной вариант, статус и будущая ссылка на решение. |
| **Слепая зона** | Важный смысл или неопределённость, отсутствующие в версионированном источнике/контракте и существующие только в чате, разговоре, памяти или несвязанной задаче. «Без слепых зон» означает отсутствие неучтённых неизвестных, а не готовность всех ответов. |
| **Исключение** | Согласованное исключение из правила методологии, источника или контракта, записанное до того, как реализация начнёт на него полагаться. |
| **Отклонение** | Намеренное проверенное расхождение принятого контракта с реализацией или поддерживаемой целью. Оно фиксирует требование, область, разницу, причину, влияние, компенсацию, владельца, статус, свидетельства и дату пересмотра, где применимо. |
| **Компенсация** | Проверенная мера, снижающая влияние исключения или отклонения на пользователя, доступность, данные, безопасность/приватность, производительность или сопровождение. |
| **Трассируемость** | Возможность пройти по стабильному требованию или идентичности через источник, контракт, реализацию, тесты, вопросы, отклонения и ревизии выпуска. |

## Проверка и отчётность

| Понятие | Значение |
| --- | --- |
| **Автоматическая проверка** | Детерминированный тест с воспроизводимым результатом. |
| **Эвристическая проверка** | Находка инструмента, указывающая на вероятный риск и требующая оценки человека. |
| **Ручная проверка** | Смысловое, продуктовое, визуальное, доступное или платформенное ревью квалифицированным человеком. |
| **Проверка в рабочей среде** | Измерение или наблюдение в объявленном окружении реализации. |
| **Валидатор** | Инструмент, проверяющий только правила из заявленного покрытия; чистый отчёт не равен полной проверке BRIDGE или WCAG. |
| **Уровень серьёзности** | Приоритет отчёта `error`, `warning` или `info`; он не заменяет решение этапа. |
| **Результат этапа** | `pass`, `pass with accepted deviations`, `blocked` или точно обоснованное `not applicable` для проверенной области. |

## Стиль и именование

- Сохраняйте машиночитаемые имена, значения тегов, идентификаторы, ссылки, перечисления и поля JSON на каноническом английском.
- Стабильные идентификаторы макета пишите по-английски в `kebab-case`, а видимые подписи — на языке продукта.
- Не называйте каждое адаптивное решение контрольной шириной, каждый скриншот — состоянием, а каждое различие — исключением.
- Различайте адаптивное преобразование, безопасный запасной вариант, исключение источника/контракта и отклонение реализации.
- Различайте пример макета и рабочие данные, а также `bridgeKey` и адрес целевой платформы.
- Различайте передачу макета, реализацию, проверку, выпуск и экспорт ресурсов: это разные операции жизненного цикла.
