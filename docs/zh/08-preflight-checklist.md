# BRIDGE 交付前检查

在实施开始之前使用此门，并在发布之前再次使用此门。它评估完整的 BRIDGE 0.11 传输：源设计、结构化合同、目标能力概况、实施证据、QA、开放问题和偏差。

较短的 [designer checklist](17-designer-checklist.md) 有助于准备。它不会取代这个门。

## 门阶段和证据

分四个阶段运行相同的清单：

|门 |所需结果 |
|--- |--- |
|设计|来源和装置暴露了所有适用的意图，无需私人解释。|
|合同|版本化的 `bridge` 信封有效，引用解析，并且无需发明行为即可开始实现。|
|实施|每个接受的要求都映射到目标行为、代码或批准的偏差。|
|质量检查/发布 |可观察的结果在声明的上下文中传递；证据和主动偏差与发布有关。|

Classify evidence as:

- **自动** — 确定性源、模式或实现检查；
- **启发式** — 一种识别可疑案例以供人类判断的工具；
- **手册** — 产品、语义、视觉、可访问性或针对特定目标的审查；
- **运行时** — 在声明的实施环境中进行测量。

仅使用基于范围的原因标记项目 `not applicable`。省略的模块不得意味着“无人检查”。

## 立即阻止者

当以下任一情况适用时，受影响的范围无法通过其大门：

- 无法识别重要元素、背景、要求、目标或源修订；
- 角色、模板、设计实例、运行时数据和目标实现被折叠成一个不明确的或位置ID；
- 所需的操作或链接没有已知的目的地、反应或可到达的目标；
- 必须发明运行时数据的含义、出处、密钥、格式、状态或隐私行为；
- 响应式拓扑在没有完整声明的转换的情况下有所不同；
- 页面根或框架构建部分禁用了本机自动布局；
- 具有至少两个可见且有意义的流程子级的通用自动布局容器已禁用自动布局；
- Figma `GROUP` 存在于不透明 `[asset]` 子树之外；记录的手动布局偏差不会抑制阻塞；
- 基本任务或内容在断点、功能、简化运动、RTL、离线或故障环境中消失，而没有映射的替代方案；
- 表单或异步路径缺乏验证、挂起、失败、恢复、焦点或公告行为；
- 适用的 WCAG 2.2 A/AA 要求没有实施路径或安全后备；
- 如果没有经过验证的后备方案，则基本目标能力不受支持；
- `unknown`、`unsupported` 或 `TBD` 决策仅存在于语音、聊天、未链接的任务或记忆中；
- 阻塞性开放问题尚未解决，或其后备方案不安全、无法访问、具有误导性、破坏性或无法测试；
- 例外或实施偏差缺乏范围、影响、缓解、所有者、证据、批准或审查日期；
- 合同、来源、实施和质量保证修订无法追溯到一个版本。

## 1. 范围、背景、修订和所有者

- [ ] 传输单元（页面、流、节或组件）具有稳定的 `transferId` 和显式范围。
- [ ] 页面、已知路线、视图、区域设置、方向、写作模式、主题、实验、角色、数据场景和目标配置文件被声明为适用。
- [ ] 源文件/页面/节点引用和不可变源修订已固定。
- [ ] `contractVersion`、`methodologyVersion` 和 `rulesVersion` 匹配受支持的版本。
- [ ] 合同修订版和目标构建/修订版是链接的。
- [ ] 设计、合同、实施、QA/可访问性和偏差批准都有负责任的所有者。
- [ ] 要求和验收标准具有稳定的 ID 和证据位置。
- [ ] 未准备好的上下文组合确定性地继承或者是明确的开放问题。

## 旧主机的选定部分配置文件

当周围文件/产品不是 BRIDGE 并且传输单元是一个新部分时，请使用此配置文件。它缩小了证据范围；它不会放弃本地 BRIDGE 要求或将主机页转换为 BRIDGE。

### 边界与证据

- [ ] 每个选定的根解析为相同的显式 `[section=<stable-id>]`；未标记的帧不会被默默地接受。
- [ ] 没有选定的部分位于不同的不透明 `[asset]` 祖先下方。仅允许使用精确的 `[section=id] [asset]` 根作为选定的不透明整体视觉对象；继承的资产边界使得范围在遍历之前被阻止。
- [ ] 该部分不包含发明的 `[page]`、`[bp]`、`[view]` 或 `[route]` 标签。选定的页面根目录是通过 **检查页面** 进行审核的，而不是此配置文件。
- [ ] `bridge.context.scope` 记录 `kind: section`、`boundary: selected-subtree`、`assetBoundary: none|selected-root-opaque`、根身份、主机状态、选择模式、上下文 ID 和 `readinessClaim: section-source-only`。
- [ ] 源文档、选定节点、图层路径和不可变修订版已固定。
- [ ] 一个选定的根声明一个请求的上下文。两个或多个显式选择的根共享相同的节 ID 并声明要比较的变体；遗留兄弟姐妹不会被隐式发现。
- [ ] 从选定的根/容器宽度推断的上下文标签被标记为 `labelSource: inferred-from-selected-root-width` 而不是作为创作意图呈现。

### 所选子树内必需

- [ ] 可编辑节根和每个符合条件的本地内容容器满足本机自动布局规则；没有剩余非资产 `GROUP` 。
- [ ] 精确选定的根 `[asset]` 停止内部遍历并使布局不适用，同时将该根保留为一个流项；`[decor]` 单独保持遍历并且仅在预期的可视层上有效。
- [ ] 本身就是 `INSTANCE` 的选定节根被报告为部分源边界。普通后代实例是受信任的原子边界：它们的内部不适用于此遍历，它们不会降低 Ready，并且它们永远不会分离以使结果看起来完整。
- [ ] 稳定身份在每个声明的选定上下文中都是唯一的；审查本地语法、内容、溢出、组件、操作和目标。
- [ ] 位于所选根内部的目标在本地解析。完整有效的 `http:`、`https:`、`mailto:` 和 `tel:` href 已编写并解析；不完整或格式错误的外部值是阻塞语法错误，而不是延迟错误。内部路由/锚点、模态/状态/表单/重置目标、组件和需要在根之外查找的数据都列在 `externalDependencies` 中，并包含所有者、状态和文件/集成审核点。
- [ ] 当请求选定的变体时，将比较它们的身份/类型、逻辑树/基数、出身、产品文本和视觉意图策略。未请求的变体是 `not requested`，而不是缺少断点。

### 延迟证据或全局证据

不要将以下内容视为已通过选定部分检查：主机页面根结构、页面/视图/路由完整性、所需的页面断点根、全局身份唯一性、向外路由/锚点/模式/状态/表单解析、父级放置和剪切/堆叠/粘性行为、页面地标和完整阅读/焦点顺序、完整旅程、运行时行为、性能、生产可访问性或 WCAG 一致性。将相关项记录为 `deferred`、`unverified-external` 或 `not evaluated: requires host/page evidence`，然后运行单独的文件/集成和实现门。

### 部分结果

- **就绪** — 所选源在声明的范围内没有错误、警告/TODO、所选根源间隙或延迟检查。单个请求的上下文可能已就绪，并且受信任的后代实例不会降低它。
- **部分** — 不存在阻止本地错误，但仍然存在警告/TODO、选定根 `INSTANCE`、延迟文件解析引用或无法区分的选定上下文。
- **阻塞** — 标记的边界丢失/无效或位于继承的不透明资产边界下方，选定的根嵌套或使用不同的部分 ID，或任何阻塞的本地发现仍然存在。

所有三种状态都是范围限定的。“就绪”意味着**部分源已为声明的选定上下文做好准备**，但绝不是页面、产品、实施或 WCAG 就绪。准确的自动覆盖范围在 [selected-section manifest](../validator/section-check-coverage.json) 中单独发布。

## 2. 身份和源映射

- [ ] 重要的创作元素具有稳定的英文 `kebab-case` 设计标识或允许的后备标签。
- [ ] 宽度/设备后缀（例如 `-375`、`-mobile` 和 `-desktop`）不会出现在逻辑标识中。
- [ ] `bridgeKey` 引用在范围和解析上是唯一的。
- [ ] 角色、`templateKey`、`designInstanceKey`、运行时记录键规则和目标映射在需要时是不同的。
- [ ] `[item=...]` 描述可重复的项目角色/类型并且可以重复；它不是唯一的装置或运行时记录标识。
- [ ] 设计装置具有稳定的设计特性，可以在重新排序后继续存在；运行时记录使用稳定的产品密钥而不是数组位置。
- [ ] 每个声明的源节点都存在于其上下文中并映射到预期的逻辑元素。
- [ ] 交互目标使用稳定的 BRIDGE 引用，并且不会与目标实现定位器混淆。
- [ ] `[decor]` 和 `[asset]` 仍然是策略标志；它们不会取代稳定的设计标识。

请参阅 [Layer naming and identity](02-layer-naming-and-identity.md) 和 [transfer contract](04-transfer-contract.md)。

## 3. 源结构、组件和包装器

- [ ] 每个页面根要么是 Figma 页面的直接子级，要么只能通过本机 Figma `SECTION` 画布组织器访问。组织者部分不携带继承的 BRIDGE 上下文，并且不会替换根；普通外部 `FRAME`/`GROUP` 包装器不透明。
- [ ] 每个 BRIDGE 页面根目录都使用本机自动布局，即使有零个或一个子级；根不能声明自己 `[asset]` 来绕过检查。
- [ ] 每个框架构建的部分都使用本机自动布局，即使有零个或一个子级，除了没有实时内容流的严格合法的整体视觉 `[asset]` 部分。
- [ ] 每个具有至少两个可见且有意义的直接流子级的通用自动布局容器都使用本机自动布局。
- [ ] 原始和叶子几何体是豁免的；不透明的 `[asset]` 子树可以保留其内部组成，而其根仍然是父级自动布局中的一个子级。
- [ ] Figma `GROUP` 不存在于 `[asset]` 子树之外。`[decor]` 不是豁免；手动布局加上原因记录了偏差，但留下了阻塞的结果。
- [ ] 相关元素在源工具中使用有意义的框架、组件、自动布局、约束和剪辑。
- [ ] 层标签不会复制节点类型、几何图形、组件源、变体或其他本机源元数据。
- [ ] 每个包装器都有分组、布局、剪辑、表面、语义、导出或交互责任。
- [ ] 页面级可重用部分来自 `Page Sections` 或在源不明确时使用显式 `[section=...]` 。
- [ ] 每个 `Page Sections` 组件的源根满足单独源审计中的自动布局规则部分；页面检查 0.9 既不解析已放置实例的源，也不将实例内部视为可编辑的页面结构。
- [ ] UI 控件继承固定组件/模板合约；实例覆盖是有意且可见的。
- [ ] 组件状态不会建模为不相关的页面根，并且页面/数据视图不会隐藏在一个组件变体中。
- [ ] 分离的组件副本、扁平资产、光栅化文本和隐藏的真相来源图层有明确的原因或被删除。
- [ ] 组件/系统继承和特定于实例的覆盖并不相互矛盾。

预期的绝对装饰在该绝对视觉节点上带有 `[decor]` 。`[decor]` 不会使自由格式容器或子树合法化。将 `[decor] [asset]` 用于作为一个不透明单元传输的复杂装饰视觉效果，而 `[bridge-exception=overlay] [reason=...]` 仅用于需要记录意图的有意覆盖。

## 4. 响应式、流畅性、容器性和定向行为

- [ ] 准备好的根使用 `[bp=...]` 作为创作的宽度锚点，而不是推断的媒体查询边界。
- [ ] 相同的逻辑树、含义、操作、数据关系和可访问性语义是跨上下文的默认设置。
- [ ] 区分视口、容器、内容/内在和功能驱动程序。
- [ ] 步进条件和流体最小/首选/最大范围涵盖创作帧之间的值。
- [ ] 每个拓扑或表示更改都具有 `fromContext`、`toContext`、条件、完整映射和保留的语义。
- [ ] 转换定义读取/焦点顺序、操作和验证奇偶性、状态/选择传输、滚动、URL/历史记录、反向转换和回退。
- [ ] 重要内容通过可达映射重新定位或公开，而不是默默删除。
- [ ] 集合基数和运行时记录标识不会更改以填充响应式网格。
- [ ] 粘性/固定 UI 保留空间并且不会遮挡锚点、内容、错误或焦点。
- [ ] 相关的安全区域、嵌套滚动所有权、视口单位、方向和屏幕键盘行为均已涵盖。
- [ ] 支持 `ltr`、`rtl`、双向文本和写入模式，具有逻辑开始/结束、图标镜像、混合值、图表轴、读取顺序和键盘顺序决策。
- [ ] QA 包括锚点、台阶上方/下方、中间宽度、嵌套容器、缩放/回流、长内容和方向固定装置。

请参阅 [Responsive and adaptive behavior](03-responsive-breakpoints.md) 和 [Variation axes](16-variation-axes.md)。

## 5. 内容、运行时数据、表格和可视化

- [ ] 编写的副本与运行时字段以及仅表示的标签或注释分开。
- [ ] 每个运行时显示都定义目的、模式、稳定密钥规则、可空性、关系和基数。
- [ ] 源所有者、数据集、聚合、刷新、陈旧性、限制、隐私、抑制和最后更新的行为是明确的。
- [ ] 区域设置、货币、单位、时区、精度、符号、舍入、范围和缺失/零/估计/不适用的值是明确的。
- [ ] 加载、空、部分、过时、错误、离线和未授权状态具有可见的反馈和恢复（如果适用）。
- [ ] 排序、过滤、分页、虚拟化、选择、批量操作、编辑、向下钻取和导出行为在存在的情况下均已完成。
- [ ] 表保留标题/名称、标题关系、比较语义和窄宽度访问。
- [ ] 图表/地图定义维度、度量、域、比例、基线、聚合、排序、编码、注释和交互。
- [ ] 颜色、悬停、画布、SVG 或动画不是获取状态、值或结论的唯一方法。
- [ ] 表、列表、摘要、详细信息或下载为复杂数据提供了适当的可访问等效项。
- [ ] 夹具涵盖零、一、典型、最大/未知、长、混合方向、缺失、重复、离群值、部分、陈旧、失败和受限数据（如果适用）。

See [Data and visualization](20-data-and-visualization.md).

## 6. 交互、状态机、形式、焦点和历史

- [ ] 导航使用真实的 `[href=...]`；非导航行为使用`[action=...]`；草稿标记仍然可见 TODO。
- [ ] 每个重要的操作都会解析为版本化反应/状态机记录。
- [ ] 状态、事件、防护、效果、待处理行为、结果、取消、超时、重试和并发是确定性的。
- [ ] 异步竞争策略可防止过时的响应替换新的状态。
- [ ] 乐观更新定义回滚、冲突处理和撤消（如果适用）。
- [ ] 字段具有稳定的绑定、可见标签、指令、值类型、所需状态、自动完成目的、约束和错误关系。
- [ ] 验证计时、客户端/服务器权限、错误摘要、第一个错误焦点、值保存、重复提交、重置和未保存更改行为是明确的。
- [ ] 对话框、抽屉、菜单、弹出窗口和披露定义初始焦点、键盘范围、转义/关闭/外部行为、嵌套、滚动锁定和焦点恢复。
- [ ] 悬停、拖动、滑动、长按和多点输入在需要时具有键盘/单指针替代方案。
- [ ] 动态插入、删除、过滤、权限更改和路由更改保留或有意移动焦点并宣布有意义的状态。
- [ ] 路径/查询/哈希/存储、`push` 与 `replace`、后退/前进、直接加载、刷新、深层链接、滚动和焦点恢复已声明。
- [ ] URL 和分析不会暴露秘密或敏感字段值。

请参阅 [Interactions and targets](05-interactions-and-targets.md) 和 [State machines and reactions](22-state-machines-and-reactions.md)。

## 7. 运动和长滚动行为

- [ ] 每个序列都有一个产品目的和作为静止内容工作的有意义的稳定状态。
- [ ] 声明驱动程序、触发器、源、范围、计时、缓动、轨道、同步和最终状态。
- [ ] 长滚动场景定义滚动条、偏移、连续/阈值映射、粘性/固定边界、保留流空间和正常流回退。
- [ ] 反向、重入、快速输入、中断、取消、调整大小、本地化、动态内容、路由恢复和深度链接是确定性的。
- [ ] 重点内容立即呈现并显示；完成不仅仅依赖于动画结束事件。
- [ ] 减少运动消除有问题的行程/视差/循环或用静态/短过渡替换它们，同时保留任务、内容、状态和焦点。
- [ ] 用户可以暂停、停止或隐藏适用的移动/自动更新内容，并且闪烁保持在适用的阈值以下。
- [ ] 不支持的动画、粘性或时间线功能使用声明的语义回退。

See [Motion and long scroll](21-motion-and-scroll.md).

## 8. WCAG 2.2 AA 可访问性配置文件

- [ ] 完整的实施范围以每个适用的 WCAG 2.2 A 级和 AA 标准为目标。
- [ ] 文档标题/语言、语言更改、地标、标题、列表、表格、标签、状态和阅读顺序匹配含义。
- [ ] 控件和字段的名称包含可见标签；仅图标控件、重复链接、说明和错误是可区分的。
- [ ] 所有功能均可通过键盘操作，无需陷阱；焦点顺序是合乎逻辑的、可见的、有意恢复的，而不是模糊的。
- [ ] 文本和非文本对比度、非颜色提示、200% 文本调整大小、320 CSS 像素等效回流、文本间距、方向和感官指示均经过验证。
- [ ] 指针目标满足 WCAG 2.2 AA 最低要求或允许的例外情况；主要触摸控制遵循所声明的更严格的产品目标。
- [ ] 拖动和复杂手势有替代方案，并且可以在适用的情况下取消指针向下事件操作。
- [ ] 表单识别错误并建议更正，保留重复信息并支持可访问的身份验证。
- [ ] 实时状态、时间限制、字幕、音频描述、文字记录、自动播放、动作和闪烁满足适用的标准。
- [ ] 复杂的图像和数据可视化公开了等效的基本信息。
- [ ] 每个响应式转换都会保留名称、角色、值、状态、关系、任务完成、焦点和帮助。
- [ ] 手动 QA 涵盖声明的浏览器/平台/辅助技术组合、键盘、屏幕阅读器、缩放/回流、间距、对比度模式、简化运动、触摸、RTL/bidi、数据状态和转换。
- [ ] 没有模型、独立组件、自动评分或不完整的流程作为 WCAG 一致性声明出现。

See the [Accessibility profile](23-accessibility-profile.md).

## 9. 资产、能力、退化和性能

- [ ] 基本内容、媒体、序列和任务结果由设计/产品声明。
- [ ] 每个目标配置文件命名平台/运行时、输入/输出功能、支持的功能和不支持的功能后备。
- [ ] 图像/视频/动画定义内在尺寸、格式、质量、焦点/作物安全区域、艺术指导、海报/预览、优先级、预加载和适用的惰性策略。
- [ ] 预期和最大数据量、页面/窗口大小、流、分页和虚拟化阈值是明确的。
- [ ] 低带宽、离线、数据保护、低功耗、减少运动、缺少 API/编解码器、内存压力和中断在适用的情况下具有可用的降级行为。
- [ ] 加载优先级不会将重要的文本/操作隐藏在非重要的媒体后面。
- [ ] 性能预算名称指标、限制、单位、所有者、目标环境、测量点和证据。
- [ ] 安全、隐私、法律、数据完整性、可访问性和基本任务完成优先于视觉保真度。
- [ ] 不支持或未知的功能是一个拥有的开放问题，而不是一个静默的适配器假设。

请参阅 [Variation axes](16-variation-axes.md) 和 [transfer contract](04-transfer-contract.md#target-capability-and-performance-profile) 中的目标/能力指南。

## 10. 路由、内容安全和目标依赖关系

- [ ] `[route=...]` 和 `[route-pattern=...]` 仅用于已知的生产路径；未知路线仍然是跟踪问题，而不是虚假 URL。
- [ ] 内部路由和锚点解析；外部、电子邮件和电话目的地使用允许的方案和打开行为。
- [ ] 模态、状态、表单、部分和锚点依赖项在接受的范围内或显式链接的外部合约内解析。
- [ ] 身份验证和权限视图不会将视觉隐藏视为授权。
- [ ] 敏感、私有、合法和用户生成的数据具有产品要求的暴露、编辑、保留和故障行为。
- [ ] 目标本机安全、平台语义和安全约束在覆盖视觉源证据时被记录。
- [ ] 分析、实验和持久状态已批准所有权，并且不会无形地改变产品行为。

## 11. 开放式问题、例外、偏差和生命周期

- [ ] 每个未解决的问题都有稳定的 ID、确切的范围、问题、所有者、阻止状态、截止日期或审核门、安全后备和状态。
- [ ] 已回答/已结束的问题将决策与更新受影响的源、合同、实施和测试联系起来。
- [ ] 异常记录有意的来源/合约规则异常；偏差记录了与已接受合同的实施差异。
- [ ] 每个异常/偏差都引用受影响的需求和确切的上下文。
- [ ] 影响涵盖用户、可访问性、数据、安全/隐私、性能和维护（如果适用）。
- [ ] 记录替代方案、缓解措施、责任所有者、审批者、证据、状态和审核/到期日期。
- [ ] 未通过 WCAG 2.2 AA 的偏差不被描述为合格。
- [ ] 临时偏差仅在合同和实施收敛且测试通过后才返回验证并关闭。
- [ ] 合同接受后的源代码更改会创建新的修订版或被证明是非语义的。
- [ ] 运行时结果反馈到规范源、合同、组件、固定装置和回归测试中。

See the [Delivery lifecycle](24-delivery-lifecycle.md).

## 12. 验证范围和证据

## 门决定记录

记录审查范围的一项决定：

- **通过** — 所有适用的标准均通过，并且不存在任何阻碍；
- **通过并接受偏差** — 偏差得到批准、缓解、证明和审查；
- **阻止** - 未解决的需求、问题、失败或不安全的回退阻止传输/发布；
- **不适用** - 仅适用于精确排除的范围，绝不适用于未经审查的区域。

该决定必须列出范围、修订、审阅者、日期、剩余问题、主动偏差、证据和下一个审阅点。如果对实施至关重要的答案仍然需要私人言语上下文，那么大门就会被封锁。
