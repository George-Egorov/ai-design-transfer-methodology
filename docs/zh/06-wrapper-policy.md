# 包装策略

包装器是 Figma 中真实的框架或组件结构。它不是 BRIDGE 标记，也不是手动层名称注释。Figma `GROUP` 不是不透明 `[asset]` 子树之外的有效内容包装器。

当包装器有助于理解或重现接口结构时，它就是有效的。仅仅因为绘图时方便而存在的包装器是噪音。

每个页面根和框架构建的部分包装器都使用本机自动布局。具有至少两个可见且有意义的流程子级的通用自动布局包装器也使用自动布局。原始/叶子几何体是豁免的，并且真正的 `[asset]` 的内部组成是不透明的；资产根仍然是其父级自动布局中的一个子级。

## 有效的包装器

当包装器执行以下其中一项工作时，它是有效的：

- 对应该一起适应的元素进行分组；
- 定义列表、网格或重复模式；
- 定义剪裁、遮罩或可见表面；
- 定义一个组的共享背景、边框、半径或阴影；
- 定义覆盖、装饰或越界视觉的范围；
- 定义语义接口区域；
- 定义目标，例如模式、状态、选项卡、手风琴或类似行为；
- 将应作为一个单元导出或处理的复杂插图分组。

这些职责解释了框架存在的原因；它们不会使手动坐标布局有效。对内容流使用自动布局，并仅对明确指定的视觉/覆盖子项使用本机绝对定位。

```text
cards-grid
  product-card-oak-chair
  product-card-wool-lamp
```

## 无效包装

劣质包装纸通常有以下迹象之一：

- 它是 `[asset]` 子树之外的Figma `GROUP`；
- 它是禁用自动布局的页面、部分或多子内容流框架；
- 一名子女且无结构性原因；
- 包装器无故出现、消失或在断点之间移动子级；
- 名称，例如 `组271`、`帧53`、`copy2`；
- 包装器改变坐标但不增加任何意义；
- 包装器隐藏了损坏的结构而不是修复它。

Bad:

```text
Frame 53
  Group 271
    hero-title
```

好（具有本机自动布局的框架）：

```text
hero-copy
  hero-title
  hero-subtitle
```

## 组和记录的偏差

使用自动布局将每个非资产 `GROUP` 替换为框架或组件。`[decor]` 不是一个例外：它仅标记确切的预期绝对视觉层。应保持不透明的复杂装饰成分是 `[decor][asset]`。

当遗留或外部控制的手动合成确实无法转换时，请将 `[bridge-exception=manual-layout] [reason=...]` 放在该确切的组上。标签记录了建议的偏差，但不抑制 `layout.group-outside-asset`；即使后来有一个单独的偏差门记录了外部对其范围和风险的接受情况，页面检查也会保留阻塞发现。

## 跨断点的包装稳定性

包装器的 Figma 设置可能会在断点之间发生变化，但包装器本身及其树位置应保持稳定。

```text
// desktop
button-group
  primary-cta
  secondary-cta

// mobile
button-group
  primary-cta
  secondary-cta
```

密钥保持稳定，因为逻辑组是相同的。

仅存在于一个断点上的包装器会更改元素结构。将其视为异常或向每个断点添加相同的有意义的包装器。如果视觉上不需要，请使用 Figma 设置将其设为中性。
