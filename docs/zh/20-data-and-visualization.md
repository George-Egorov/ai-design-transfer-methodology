# 数据与可视化契约

BRIDGE将数据显示视为产品合同，而不是排列在矩形中的样本副本。可转移的设计说明了数据的含义、数据来自何处、如何格式化、用户可以执行哪些操作以及当理想数据集不可用时会发生什么。

![Pipeline from data semantics to an accessible responsive presentation](../assets/diagrams/data-contract-pipeline.svg)

*一个语义数据集可能有多个声明的表示。格式化和响应式组合不得改变其含义。*

## 合同中包含哪些内容

对于每个表、网格、指标、列表或图表，记录：

|关注|所需的决定|
|--- |--- |
|目的|显示屏回答的问题及其支持的决策。|
|架构|字段键、值类型、可为空值、标识符和关系。|
|基数 |最小值、典型值、最大值、分页/窗口以及总数是否已知。|
|出处 |源系统或所有者、聚合方法、刷新时间和新鲜度/过时规则。|
|演示|列/系列含义、顺序、分组、排序、过滤、比较基线和精度。|
|格式|区域设置、时区、货币、单位、符号、舍入、缺失值标记和日期/数字表示法。|
|州 |加载、空、错误、部分、陈旧、离线和未经授权的行为。|
|反应灵敏 |相同树行为或具有语义奇偶性的声明转换。|
|无障碍 |名称、描述、标题/关系、键盘操作和非视觉等效项。|
|信任|数据限制、估计、样本大小、隐私/禁止规则和最新更新信息。|

Figma 中的示例值是固定装置。它们不是模式、最大长度、精度规则或运行时事实来源。

## 角色：内容、数据显示和控件

- **内容**是创作的产品副本：标题、解释、脚注或注释。
- **运行时数据**由服务、CMS、计算、传感器或用户输入提供。
- **数据显示** 将运行时数据映射到表格、网格、指标、列表、地图或图表。
- **控件**更改查询或表示：过滤器、排序、日期范围、分页、向下钻取或系列可见性。
- **出处**告诉用户和实施者为什么一个值可以被信任以及它的最新程度。

保持这些角色的不同。图表标题不是数据字段；而是数据字段。突出显示的最大值不是新值；过滤器芯片不是结果集合的一部分。

## 使用短层标签，保持丰富的合约结构

层名称和现有的 BRIDGE 标签应仅公开审阅者在设计中需要的锚点：

```text
Revenue [section=revenue-overview]
  period-filter
  revenue-chart
  revenue-table
  data-status
```

请勿使用 `[series-revenue]`、`[currency-usd]`、`[timezone-utc]` 等名称以及数十个类似标签对整个架构进行编码。附加或导出一份由 `revenue-chart` 键入的结构化合约：

> **非独立模块片段。** 此摘录仅显示 `bridge.data` 并有意省略必需的信封字段。在交换或完整合同验证之前，将其插入 [transfer contract](04-transfer-contract.md#required-envelope) 中所需的 `bridge` 信封中。

```json
{
  "bridge": {
    "data": {
      "displays": [{
        "displayId": "revenue-chart",
        "purpose": "Compare recognized revenue with target by month",
        "source": { "owner": "finance-analytics", "dataset": "recognized-revenue", "refresh": "daily", "staleAfter": "PT36H" },
        "dimensions": [{ "key": "month", "type": "year-month", "timeZone": "UTC" }],
        "measures": [
          { "key": "actual", "type": "decimal", "currency": "USD", "aggregation": "sum" },
          { "key": "target", "type": "decimal", "currency": "USD", "aggregation": "sum" }
        ],
        "format": { "locale": "user", "notation": "compact", "maximumFractionDigits": 1 },
        "states": ["loading", "empty", "error", "partial", "stale"],
        "accessibleEquivalent": "revenue-table"
      }]
    }
  }
}
```

结构化元数据可进行版本控制、可审查且与目标无关。它可能存在于 Figma 插件数据、sidecar 文件或适配器有效负载中，但它必须引用稳定的 BRIDGE 身份并随切换一起移动。

## 表格

A data table contract declares:

- 标题或易于理解的名称，以及有用的简短摘要；
- 行标识和列键；
- 标题范围、分组标题以及标题和数据单元格之间的关系；
- 默认排序以及排序是客户端还是服务器端；
- 过滤器语义、主动过滤器公告和重置行为；
- 分页、无限加载或虚拟化，包括总计数行为；
- 选择模型、批量操作范围和跨页面持久性；
- 可编辑单元格验证和保存/恢复行为；
- 窄宽度下的溢出行为，无需默默隐藏重要字段。

当用户跨行和列比较值时使用语义表。视觉卡布局并不是放弃关系的理由。遵循 [WAI tables tutorial](https://www.w3.org/WAI/tutorials/tables/) 来获取标头关联模式。

## 网格、列表和重复卡片

声明项目架构与 Figma 框架适合的固定装置数量无关。指定稳定的项目标识、排序、分组、最小/最大/未知计数、分页、重复项、缺失媒体以及长值或本地化值。

响应式列更改不会更改基数：

```text
product-grid
  product-card-oak-chair
  product-card-wool-lamp
  product-card-steel-desk
  product-card-cork-stool
```

这些是稳定的**设计夹具实例**键，而不是数组位置，也不是运行时数据库 ID。重复的数据项具有单独的标识：`templateKey` 表示可重复使用的卡，`designInstanceKey` 表示创作的固定装置，`runtimeDataKey` （或其他产品记录密钥）用于排序、过滤、分页和实时更新后的协调。结构化映射（不是 `-1`、`-2` 层后缀）定义了关系。切勿仅仅为了满足合同而暴露机密后端标识符。

如果移动设备故意加载不同的记录窗口，则查询/分页合同必须如此说明。不要仅仅为了生成完整的最后一行而删除固定卡。

## 图表和地图

每个图表合约均注明：

1.分析问题和合适的图表形式；
2. 维度、度量、单位、域、聚合、基线和排序；
3. 完整的量表行为，包括需要时的零基线和异常值的处理；
4.颜色、形状、线条样式、尺寸、注释的含义；
5. 悬停、聚焦、选择、缩放、平移、向下钻取和重置行为；
6. 工具提示内容和格式；
7. 易理解的名称和主要模式的简明摘要；
8. 通过数据表、列表或可下载的等效项访问值。

切勿仅通过颜色来传达系列或状态。确保标签和标记满足适用的对比度要求，保持工具提示可通过键盘和指针访问，并且不要将画布/SVG 图片作为信息的唯一表示形式。[WAI images tutorial on complex images](https://www.w3.org/WAI/tutorials/images/complex/) 描述了图表和图表的文本替代方案。

## 格式即语义

声明区域设置敏感的格式而不是复制可见的标点符号：

- 货币价值包括货币和货币显示政策；
- 百分比区分 `0.25` 和 `25`；
- 计量包括单位和转换/舍入政策；
- 时间戳包括源区域、显示区域、夏令时行为和粒度；
- 范围定义包容性和开始/结束语义；
- 缺失、零、抑制、估计和不适用的值在表示不同事物时使用不同的状态。

不要让紧凑的表示法、舍入或截断使总数相互矛盾。在用户需要的地方应该保持完全的精度。

## 所需数据状态

|状态|合同问题|
|--- |--- |
|正在加载 |之前的数据是否保留？进度是确定的吗？宣布了什么？|
|空 |查询是否有效但没有结果？存在哪些恢复措施？|
|错误 |哪个操作失败了，什么仍然可用，可以重试吗？|
|部分|缺少哪个子集，用户可以对不完整的结果采取行动吗？|
|陈旧|它有多久了，为什么显示它，以及如何请求刷新？|
|离线 |缓存什么、排队什么操作以及如何报告重新连接？|
|未经授权 |内容是否被隐藏、编辑或被许可请求替换？|

骨架必须类似于最终的结构，而不是假装是真实的内容。实时更新必须保留焦点和选择，并且仅在对用户产生重大影响时才宣布。

## 响应式数据转换

默认情况下使用相同的逻辑树。表格可以滚动，列可以调整大小，图表可以重排，图例可以移动，标签可以换行，而不会出现结构异常。

当可用的演示文稿真正发生变化时（表格变为卡片，多系列图表变为小倍数，或者内联细节变为披露），请声明响应式转换。它必须记录：

- 来源和结果身份；
- 容器或视口状况；
- 字段/系列映射，不会无声地失去意义；
- 阅读、专注和行动顺序；
- 省略的细节的位置以及用户如何访问它们；
- 状态、选择、过滤器和 URL/历史记录保存；
- 每个演示文稿中的无障碍同等内容。

较小的屏幕不允许删除比较字段、出处或恢复操作。请参阅[Responsive breakpoints](03-responsive-breakpoints.md)。

## 数据审查门

仅当审阅者可以回答时，数据显示才准备就绪：

- 我们可以用零发明字段或格式来实现它吗？
- 夹具是否涵盖零、一、典型、最大、长、缺失、陈旧、部分和失败的数据？
- 源、刷新、单位、精度和时区是否明确？
- 排序、过滤、分页、选择和向下钻取是否有完整的反应和状态？
- 狭隘的表述是否保留了意义和任务完成情况？
- 键盘或屏幕阅读器用户能否获得相同的值和结论？
- 隐私、抑制、估计和限制在需要时是否可见？
