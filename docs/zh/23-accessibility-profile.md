# 无障碍配置

BRIDGE 最终实现的目标是 **WCAG 2.2 AA 级**。此概要文件将该目标转化为设计、合同、实施和质量保证责任。它并不声称单独的 Figma 文件就可以符合：一致性是在整个产品和所有适用的 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 成功标准上进行评估的。

![BRIDGE coverage from design evidence through implementation and accessibility QA](../assets/diagrams/bridge-coverage-map.svg)

*设计证据、结构化意图、语义实现和面向用户的测试都是必需的。没有单层证明可访问性。*

## 规范基线

- 目标 WCAG 版本：**2.2**。
- 目标级别：**AA**，包括每项适用的 A 级和 AA 成功标准，而不仅仅是此处总结的项目。
- 范围：完整的页面和流程、响应式和本地化变体、经过身份验证的状态、错误、覆盖、嵌入内容和支持的平台。
- 支持辅助功能的技术：由实施团队声明并使用代表性浏览器和辅助技术进行测试。
- 即使技术上适用 WCAG 例外，此配置文件中仍然需要更严格的产品要求。

使用 [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/) 来实现预期的小部件交互模式。更喜欢本机平台语义和控件；ARIA 不会修复不合适的交互模型。

## 责任矩阵

|舞台|所需证据|
|--- |--- |
|设计|阅读顺序、名称、标签、状态、焦点行为、对比度、回流、目标大小、替代方案、减少运动。|
|合同|稳定的语义角色/关系、反应焦点和公告、数据等价物、异常和所有者。|
|实施|本机语义、键盘行为、可访问性 API 公开、首选项处理、响应行为。|
|质量保证 |自动检查加上键盘、缩放/回流、屏幕阅读器、对比度、运动、媒体和基于任务的手动测试。|

不要将可访问性作为未指定的清理步骤交给开发人员。不要将自动扫描视为一致性证明。

## 语义和阅读顺序

A page contract identifies:

- 一份描述性页面标题、文档语言和语言更改；
- 适当时，页眉、导航、主要内容、补充内容、表格和页脚的地标；
- 逻辑标题层次结构，描述部分而不是视觉字体大小；
- 根据含义列出、表格、引文、标签、状态和关系；
- 替代文本或图像的明确装饰分类；
- 有意义的 DOM/可访问性顺序与视觉定位无关。

使用现有 Figma 结构、组件源、稳定名称、`[decor]` 和结构化可访问性元数据作为证据。不要为每个 HTML 元素创建平面标签。目标适配器选择本机元素，同时保留声明的语义。

## 可访问的名称、标签和描述

每个控件和字段都有一个与其可见标签匹配或包含其可见标签的编程名称。仅图标控件需要明确的稳定名称。附加描述连接指令、单位、约束、错误消息和后果，而无需替换标签。

Requirements:

- 可见文本是可访问名称的默认来源；
- 同一控件在断点和状态之间保持相同的名称，除非其操作发生变化；
- 占位符文本不是标签；
- 链接文本在上下文中描述其目的地；
- 重复的“了解更多”链接可以获得独特的上下文；
- 状态徽章以文本形式显示状态，而不仅仅是颜色；
- 在失败之前解释必填字段和接受的格式；
- 错误识别领域、原因和已知的纠正。

当设计源没有更好的属性时，简短的 `[a11y-label=...]` 可以澄清仅图标链接/控件。丰富的帮助、错误和关系数据属于结构化合同，而不是附加的层名称标签。

## 键盘和焦点

所有功能都必须可以通过键盘或等效的顺序输入使用，而无需陷阱。合同定义：

- 基于语义结构的逻辑Tab顺序；
- 当识别的模式需要时，小部件内部箭头键行为；
- 每个主题和状态下的可见焦点样式；
- 对话框、抽屉、菜单、路线更改、验证、删除和动态更新的初始和恢复焦点；
- 重复块的跳过或旁路机制；
- 当存在粘性标题、cookie 横幅、覆盖层或滚动容器时聚焦可见性；
- 拖动、基于路径的手势、悬停和仅指针操作的替代方案。

不要使用正的 `tabindex` 或视觉顺序来代替正确的源顺序。在 AA 级，重点组件不得被作者在 [Focus Not Obscured (Minimum)](https://www.w3.org/TR/WCAG22/#focus-not-obscured-minimum) 下创建的内容完全隐藏。BRIDGE还需要有意的焦点指示器，而不是依赖于不确定的浏览器/主题对比。

## 视觉要求

实施必须至少满足：

- 对于 WCAG 定义的大文本，文本对比度为 **4.5:1** 或 **3:1**；
- **3:1** 基本用户界面组件和图形对象的对比度；
- 信息不仅仅通过颜色传达；
- 可在**200% 文本大小调整**时使用的内容；
- 没有以 **320 CSS px** 等效宽度滚动的二维页面回流，真正需要二维布局的内容除外；
- 用户应用 WCAG 文本间距覆盖时不会造成任何损失；
- 支持纵向和横向，除非必须有一个方向；
- 不仅仅依赖于形状、颜色、声音、位置或感官语言的可见指令。

验证真实呈现的状态，而不是令牌名称。名为 `accessible-blue` 的颜色标记在实际背景和不透明度下无法证明任何内容。

## 目标大小和指针输入

WCAG 2.2 AA [Target Size (Minimum)](https://www.w3.org/TR/WCAG22/#target-size-minimum) 要求指针目标至少为 **24 × 24 CSS 像素** 或满足其间距/异常条件之一。BRIDGE 建议主要触摸控制使用 **44 × 44 CSS 像素** 激活区域，并使用 24 像素标准作为不可​​协商的 AA 底板。

Also define:

- 相邻破坏性或高频目标的充分分离；
- 取消/撤消停机事件激活（如果适用）；
- 拖动操作的非拖动替代方案；
- 多点或路径手势的单指针替代方案；
- 在窄宽度和缩放下保持可见和可操作的标签。

不要只放大绘制的图标而留下一个微小的激活框。

## 表单、错误和身份验证

表格遵循 [state-machine contract](22-state-machines-and-reactions.md) 并且必须提供：

- 标签、说明、目的/自动完成元数据（如适用）；
- 错误识别和已知的纠正建议；
- 复杂表单的错误摘要和确定性焦点/公告行为；
- 根据需要审查、确认、撤销或检查法律、财务和数据更改提交的内容；
- 验证或服务器故障后保留的值；
- 除非有允许的例外情况，否则不得在同一流程中重复输入先前提供的信息；
- 身份验证不仅仅依赖于认知功能测试，还支持密码管理器和粘贴。

禁用的提交按钮不能是表单不完整的唯一指示。

## 动态内容和异步状态

加载、结果、错误、后台保存、连接更改和其他有意义的更新需要可见的反馈，以及在适当的情况下礼貌或自信的实时公告。宣布：

- 宣布的内容和时间；
- 现有内容是否变得繁忙、陈旧或不可用；
- 如何合并重复的更新以避免噪音；
- 焦点是保持不变还是由于特定任务的原因而移动；
- 用户如何发现插入的内容；
- 超时延长、重试和恢复控制。

不要仅仅为了让屏幕阅读器宣布状态而移动焦点。使用语义状态机制并尽可能保留用户的位置。

## 数据、图表和复杂的视觉效果

应用 [data and visualization contract](20-data-and-visualization.md)。表保留表头关系；图表和地图具有名称、摘要、非颜色编码、键盘可访问的交互，以及在适当的情况下通过表格/列表/下载访问基础值。装饰性视觉效果不属于可访问性树。

复杂的图像需要立即的简短替代方案以及足以获得相同基本信息的附近或链接的细节。[WAI complex-images tutorial](https://www.w3.org/WAI/tutorials/images/complex/) 提供官方模式。

## 动作、时间、闪烁和媒体

应用 [motion contract](21-motion-and-scroll.md)。尊重简化运动偏好，将任务保留在静态回退中，提供用于限定移动/自动更新内容的控制，并且永远不要超过 WCAG 闪存阈值。

对于时间限制，声明警告、延期、保存和重新验证行为。对于预录制和现场音频/视频，请提供所有适用的 A/AA 级标准所需的字幕、音频描述、文字记录、媒体控制和替代方案。在适用的标准下，必须避免或控制自动播放音频。

## 响应式转换

A responsive transformation must preserve:

- 可访问的名称、角色、值、状态和关系；
- 阅读和焦点顺序；
- 键盘和指针任务完成；
- 错误、状态、出处和帮助；
- 访问隐藏在披露背后的内容；
- 切换演示时焦点/历史恢复。

可视化表格到卡片或导航到菜单的转换并不是删除标题、关系或操作的语义许可。测试容器驱动的更改以及视口断点。

## 方向、写作模式和双向内容

可访问性审查必须包括支持的 `ltr`/`rtl` 方向和书写模式，而不仅仅是翻译的字符串。保留逻辑阅读和键盘顺序；不要强迫它遵循视觉镜像。测试混合方向的人名、电话号码、日期、ID、代码和数字；适当的图标镜像；图表轴和类别顺序；重点指标；错误放置；和公告。使用逻辑开始/结束关系并声明嵌入值的基本方向，以便辅助技术接收可理解的序列。

## 结构化可访问性元数据

仅将结构化元数据用于源和组件无法表达的意图：

> **非独立模块片段。** 此摘录仅显示 `bridge.accessibility` 并有意省略必需的信封字段。在交换或完整合同验证之前，将其插入 [transfer contract](04-transfer-contract.md#required-envelope) 中所需的 `bridge` 信封中。

```json
{
  "bridge": {
    "accessibility": {
      "profile": { "standard": "WCAG", "version": "2.2", "level": "AA" },
      "elements": [{
        "element": "revenue-chart",
        "name": "Monthly revenue compared with target",
        "description": "Actual revenue exceeded target in 8 of 12 months",
        "details": "revenue-table",
        "readingOrder": ["chart-title", "chart-summary", "revenue-chart", "revenue-table"],
        "reducedMotion": "static-series",
        "testIds": ["a11y-chart-keyboard", "a11y-chart-values"]
      }]
    }
  }
}
```

此元数据补充（而不是取代）可见内容和实现语义。

## 所需的质量保证矩阵

测试代表至少要完成以下任务：

1. 仅键盘，正向和反向顺序，包括覆盖和失败；
2. 团队声明的支持辅助功能的平台组合上的屏幕阅读器加键盘；
3. 200% 文本调整大小和 400% 浏览器缩放/重排（窄等效宽度）；
4. 文本间距覆盖和长本地化；
5. 强制/高对比度或平台对比度模式（如果支持）；
6.减少运动和禁用/不支持的首选动画机制；
7. 指针和触摸目标大小、取消、手势替代和方向；
8. 针对可检测故障的自动规则，然后进行手动审查；
9. 加载、空、部分、陈旧、错误、离线、验证和权限状态；
10.各宣告响应式转型。
11.支持RTL/双向和写入模式夹具，包括图表和混合标识符。

记录浏览器、平台、辅助技术/版本、场景、预期结果、实际结果和证据。通过一种屏幕阅读器/浏览器组合并不能证明普遍支持。

## 例外情况和一致性声明

异常记录必须确定确切的标准或 BRIDGE 要求、受影响的范围、证据、用户影响、原因、所有者、缓解措施、批准和审查/到期日期。没有证据和缓解计划的“技术限制”是不可接受的。

请勿声称模型、孤立组件、自动评分或不完整旅程符合 WCAG 要求。只有在根据所有适用标准对已实施的完整范围页面和流程进行评估并准确披露已知故障后，发布才可以声明符合性。
