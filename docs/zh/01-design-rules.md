# 设计规则

BRIDGE-ready 设计在传输之前必须是可以理解的。在 Figma 中，这来自正确编写的结构、稳定的名称和明确的产品意图，而不是来自手写的技术标签。

## 1.不要重复Figma元数据

设计者不得为 Figma 已作为数据公开的技术属性编写图层名称标签：

- 节点类型：文本、图像、矢量、组件实例；
- 自动布局：方向、间隙、填充、对齐、换行；
- 框架、组和组件层次结构；
- 定位、约束、剪辑内容、尺寸；
- 填充、描边、效果、蒙版；
- 源组件、变体、组件属性。

适配器从 Figma 读取这些。仅当 Figma 不知道产品意图时才需要手动标签。

## 2. 设计师手动声明的内容

层名称仅声明传输意图：

- 页面、已知的真实生产路线、断点和视图；
- 分段合同；
- `href` 用于已知链接，`[link]` 用于草稿未知链接；
- `action` 用于已知控件/按钮，`[control]` 用于草案未知操作；
- 表单字段；
- 模式或状态目标；
- 装饰视觉；
- 全部出口资产；
- 无法安全推断的高度、溢出或显式异常。

## 3. 使用本机自动布局构建结构

相关元素必须编写为真实的 Figma 结构，并且其内容流必须明确：

- 副本和按钮存在于有意义的父母体内；
- 卡片位于共享列表或网格内；
- 章节标题、副本和 CTA 位于该章节内；
- 重复的项目结构一致；
- 随机 `Frame 53`、`Group 271` 和 `copy 2` 层不是就绪切换的一部分。

如果元素应该一起适应，它们一定不能是松散的、自由浮动的兄弟姐妹。仅保留手动绘制坐标的框架不是可转移的布局契约。

### 阻止自动布局策略

![Auto Layout gate showing required page, section, and content-container flow; GROUP and page-root asset blockers; and the narrow asset, absolute-layer, and instance boundaries](../assets/diagrams/auto-layout-gate.svg)

*大门是结构性的：本机流通过，而不透明资产外部的手动容器和 GROUP 节点仍然阻碍发现。*

在这些边界处使用原生 Figma 自动布局（垂直、水平或网格）：

|源节点|所需政策 |
|--- |--- |
|BRIDGE 页面根 |始终使用自动布局，即使有零个或一个子级。页面根不能将自己标记为 `[asset]` 来绕过此规则。|
|框架构建页面部分|始终使用自动布局，即使有零个或一个子级。仅当整个部分有意作为一个视觉对象交付并且不包含实时文本、控件、表单、数据或内容流时，该部分才可能是不透明的 `[asset]` 。|
|支持通用自动布局的内容容器 |当至少有两个可见且有意义的直接子级参与内容流时，使用自动布局。|
|原始或叶子几何形状 |豁免，因为它不拥有内容流。|
|不透明 `[asset]` 子树 |内部成分除外。资产根仍然作为一个子项参与其父项的自动布局。|
|组件实例|页面检查将放置的实例视为原子边界，并且不解析或检查其源组件。根据此策略单独审核可编辑源根目录。|

**有意义的流程子项**是一个可见的直接子项，它承载内容、交互、语义结构或可重用的视觉项。隐藏/存档层和正确声明的绝对视觉子级不会创建通用内容流。页面和节根不使用两个子阈值：它们的自动布局要求是无条件的。

### GROUP 节点不是布局容器

位于 `[asset]` 子树之外的 Figma `GROUP` 是一个阻塞错误，无论其子树数量如何。将其替换为框架或组件并定义本机自动布局。`[decor]` 不会使 GROUP 有效，并且绝不能用作结构旁路。

如果转换确实不可能，请在 GROUP 本身上记录建议的偏差：

```text
legacy-lockup [bridge-exception=manual-layout] [reason=vendor-master-art]
```

两个标签必须位于确切的组中。他们记录了不可避免的手动合成，但**不抑制** `layout.group-outside-asset`；页面检查仍然报告阻塞发现。单独的偏差接受门必须审查其范围、影响、缓解、证据、所有者、批准者和审查日期。该例外也永远不会免除父页面、节或内容流容器。

### 绝对视觉层次

预期的绝对装饰可以是叶子视觉层，例如：

```text
hero-glow [decor]
```

`[decor]` 仅在 Figma 定位为绝对的确切视觉层上有效。它不授权任意自由形式的子树，也不放弃任何祖先的自动布局或组规则。如果复杂的装饰构图应保持不透明，请使用 `[decor] [asset]`；如果无法以其他方式对有意的非装饰性覆盖进行建模，请在确切的覆盖节点上使用 `[bridge-exception=overlay] [reason=...]` 。

```text
home [page=home] [bp=1440] [view=default]     // FRAME, vertical Auto Layout
  hero [section=hero]                          // FRAME, vertical Auto Layout
    hero-copy                                  // FRAME, vertical Auto Layout
      hero-title                               // TEXT leaf
      hero-subtitle                            // TEXT leaf
    hero-glow [decor]                          // intended ABSOLUTE visual leaf
    hero-art [decor] [asset]                   // intended ABSOLUTE opaque visual
```

## 4. 图像、装饰和资产的含义不同

内容图像携带信息。如果删除它会改变含义，请为该图层指定一个稳定的名称。

装饰是视觉装饰。如果删除它仍保留意义，请使用布尔视觉意图标签 `[decor]` 对其进行标记。

`[decor]` means:

- 该层是装饰性的，而不是产品内容；
- 在 `[asset]` 子树之外，它是确切预期的绝对视觉层，而不是流容器或自由形式组；
- 它不应进入可访问性树，并且可能是 `aria-hidden`；
- 它不需要替代/内容语义；
- 它仍然保持稳定的响应身份，并且在断点之间一定不会消失；
- 它永远不会将页面、部分、容器、组或任意子树排除在上述结构策略之外。

资产是一种视觉效果，应作为整个文件导出，而不是从内部层重建。使用布尔策略标签 `[asset]` 对其进行标记。

`[asset]` means:

- 将视觉效果作为一个整体导出或使用；
- 不要从内部层重建它；
- 内部自由组合对于结构布局检查是不透明的；
- 根资产层跨断点仍然保持稳定的响应身份，并作为一项参与父级的自动布局；
- 它不能仅仅为了沉默布局结果而应用于整个 BRIDGE 页面根。

当图层已经有一个好的稳定名称时，更喜欢布尔标签：

```text
product-photo
article-cover
author-avatar
snow-bg [decor]
hero-glow [decor]
promo-poster [asset]
lab-illustration [asset]
sneg [decor] [asset]
```

旧的值形式只是不良/默认图层名称的后备：

```text
Frame 182 [decor=snow-bg]
Group 91 [asset=promo-poster]
```

## 5. 根框架是具体的页面或节断点

根框架应该携带稳定的页面/视图/断点数据。只有在已知真实生产路线的情况下才添加`[route=...]`：

在 Figma 画布上，此根可能是 Figma 页面的直接子级，也可能是仅通过本机 Figma `SECTION` 组织者到达的后代。这些部分位于传输的页面层次结构之外：它们的名称和标签不会被继承，并且它们不会放松根的自动布局契约。标记根之外的普通 `FRAME` 或 `GROUP` 不是透明组织者。

```text
home [bp=1920] [view=default] [page=home] [route=/]
home [bp=375] [view=default] [page=home] [route=/]
```

如果还不知道路由，请忽略它，而不是发明一个假的生产 URL：

```text
contacts [bp=1440] [view=default] [page=contacts]
```

断点是同一页面的不同宽度，而不是含义或结构的新版本。

## 6. 裁剪和溢出是决定

如果框架是卡片、视口、遮罩或受约束的表面，则其溢出行为必须是有意的。

来自 CMS、管理面板、目录或本地化的文本不得依赖手动换行符。它应该按其文本区域的宽度换行，并具有明显的溢出行为。

## 7. 原生/可编辑元素保持原生

文本、按钮、表单字段、简单的形状和图标不应无缘无故地变成图像。导出的资源仅适用于目标实现不应或无法重建的复杂视觉效果。

## 8. 该方法与平台无关

BRIDGE 不依赖于一种工具。Figma 是主要的设计源，但契约应该转移到前端框架、静态 HTML/CSS、可视化编辑器、移动 UI 或内部设计系统中，而无需猜测。
