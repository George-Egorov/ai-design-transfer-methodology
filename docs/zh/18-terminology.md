# BRIDGE 术语表

这是面向契约、实施、QA 和偏差的进阶参考。如果你准备第一份文件，请先阅读[设计师快速起步](00-designer-quick-start.md)。

## 使用规则

面向人的解释可能是本地化的。机器可读的层标签、JSON 字段名称、规则 ID、枚举值和稳定引用保留其规范的英语形式。熟悉的单词不会覆盖其下面的 BRIDGE 定义。

## BRIDGE 名称

|术语 |桥的含义|
|--- |--- |
|**断点** |声明的响应上下文：创作的宽度锚点以及视口、容器、流体、内在、方向和功能相关的规则。断点不仅仅是屏幕截图或推断的 CSS 媒体查询。|
|**角色** |元素、显示、操作或所有者的逻辑目的，首先从本机源元数据派生，并在需要时明确 BRIDGE 意图。|
|**身份** |跨角色、模板、设计实例、运行时数据和目标实现的可追踪映射。它不是一个重载的 ID。|
|**依赖关系** |成果发挥作用所需的数据、行动、目标、状态、焦点/历史影响、能力和继承契约。|
|**几何** |可重现的精确、阶梯、流体、内在、空间和时间属性，包括边界、间距、文本度量、范围和运动轨迹。|
|**例外** |源或合同规则的有意的、有范围的例外，包括原因、影响、缓解、所有者、证据和审查。响应式转换或实施偏差并不自动成为例外。|

## 源面和接触面

|术语 |意义|
|--- |--- |
|**设计/来源证据** |证明创作意图的版本化源文件、页面、节点、组件、本机元数据、固定装置、原型、注释或资产。Figma 是一种可能的来源，而不是该方法的要求。|
|**根** |页面、视图、响应式上下文或独立部分的顶级源对象。|
|**Figma 部分组织者** |原生 Figma `SECTION` 用于对画布上的对象进行分组。它在 BRIDGE 页根发现期间是透明的，并且与携带 `[section=...]` 的产品部分不同。它的名称/标签不会成为页面上下文。|
|**稳定层名称** |人类可见的英文 `kebab-case` 设计锚点，不会对视口宽度、设备标签或运行时列表位置进行编码。|
|**短层标签** |规范的括号标记，例如 `[page=catalog]`、`[href=/catalog]` 或 `[item=product]` 仅用于必须在图层树中保持可见的简洁意图。|
|**结构化 `bridge` 元数据** |对于层名称而言过于丰富的关系的命名空间数据：身份映射、数据显示、响应式转换、反应、运动、可访问性、功能、生命周期、问题和异常。|
|**桥梁合同** |源证据、短锚、结构化元数据、需求和验收标准的版本化、独立于目标的组合交付给实施和质量保证。|
|**所需信封** |植根于 `bridge` 的完整有效负载，具有受支持的版本字段以及 `source`、`context` 和 `identity`；适用的模块被添加到该信封内。|
|**模块片段** |诸如 `{ "bridge": { "data": … } }` 之类的非独立摘录用于解释一个模块。在交换或验证作为完整合同之前，必须将其插入所需的信封中。|
|**要求** |行为或质量的稳定的、有范围的陈述，其结果可以被验证。|
|**验收标准** |确定需求是否在声明的上下文中传递的可观察条件。|
|**证据** |支持需求结果的可链接源、合同、实施、测试、测量或审核工件。|
|**修订** |与生命周期决策相关的源、合同、实施或证据的不可变版本。|

## 身份和参考资料

|术语 |意义|
|--- |--- |
|**`bridgeKey`** |一个逻辑创作元素的稳定合同参考。它链接记录，但不会取代五个身份维度。|
|**角色** |元素的用途，例如导航、产品数据项、状态或表单字段。|
|**模板** |拥有结构和继承行为的可重用组件或节定义；在需要时由 `templateKey` 标识。|
|**设计实例** |已声明上下文中的一个创作事件及其源节点；由 `designInstanceKey` 标识。|
|**运行时数据** |渲染真实数据时使用的集合、稳定的记录键规则和可选的夹具绑定；`runtimeDataKey` 绝不是数组位置。|
|**目标实现** |在目标平台上实现契约的组件、本机控件、视图、路由、实体或定位器。|
|**互动目标** |反应通过稳定的 BRIDGE 参考达到的模式、状态、形式、路线或元素。它与目标实现映射不同。|
|**`[item=…]` 值** |可重复的项目角色/类型，例如 `[item=product]`。兄弟项目可能有意使用相同的值。它们独特的创作和运行时身份来自稳定层名称/`bridgeKey`、`designInstance`和`runtimeData`，而不是来自`[item]`。|
|**夹具钥匙** |用于重现场景的稳定创作的示例绑定。它可以标识橡木椅示例，但不得将其视为生产记录密钥。|

## 响应式和变异性语言

|术语 |意义|
|--- |--- |
|**响应上下文** |具有声明的视口或容器驱动程序以及任何相关变化轴的命名布局上下文。|
|**断点锚点** |由根 `[bp=…]` 表示的准备宽度。它是一个创作的参考点，而不是自动的 CSS 边界。|
|**同树默认** |逻辑元素、含义、操作、数据关系和可访问性语义在响应式上下文中保持等效的规则，除非转换另有声明。|
|**结构转型** |当拓扑或表示模型更改时，`fromContext` 和 `toContext` 之间声明的映射。它记录条件、源/目标映射、保留的语义、顺序、状态转移、历史、反向行为和回退。这也不例外。|
|**阶梯式行为** |在明确条件下发生变化的离散规则。|
|**流畅的行为** |在声明的最小、首选和最大界限之间连续得出的值。|
|**内在行为** |布局由内容、可用空间或目标本机基元而不是固定宽度决定。|
|**变化轴** |用户、内容、环境或产品维度，例如区域设置、主题、方向、写作模式、角色、数据状态、输入、动作偏好或功能。|
|**方向和书写模式** |声明的 `ltr`/`rtl` 和水平/垂直书写上下文，包括逻辑顺序/属性以及显式镜像与非镜像决策。|
|**双向内容** |混合方向文本，例如带有拉丁 ID、数字、日期或 SKU 的阿拉伯标签，需要隔离、排序、格式化、图表轴、键盘顺序和测试夹具决策。|

## 内容、数据和可视化

|术语 |意义|
|--- |--- |
|**创作内容** |其批准价值是设计/源合同一部分的副本或媒体。|
|**运行时数据** |实施后由服务、CMS、用户、设备或目标环境提供的值。|
|**数据显示** |通过结构化数据回答已声明问题的表格、网格、列表、卡片集、图表、地图、指标或其他演示文稿。|
|**数据模式** |显示或反应预期的字段类型、稳定键、可空性、关系和基数。|
|**夹具** |正常、边界、故障、本地化、方向、隐私或可访问性场景的版本化示例数据。|
|**出处** |数据集/源、责任所有者、聚合、刷新行为、限制、隐私和解释值所需的最新更新信息。|
|**数据状态** |可区分的条件，例如 `loading`、`empty`、`partial`、`stale`、`error`、`offline` 或 `unauthorized`，并在适用的情况下提供反馈和恢复。|
|**格式语义** |影响含义而不是装饰的区域设置、单位、货币、时区、精度、舍入、符号、范围和缺失/零/估计规则。|
|**无障碍同等** |表格、列表、摘要、详细视图或下载，可展示复杂视觉效果的基本值和结论，而无需单独依赖颜色、悬停、画布或动画。|

## 交互和状态

|术语 |意义|
|--- |--- |
|**反应** |对事件的版本化响应，包括先决条件、状态更改、效果、结果、焦点、公告和历史行为。|
|**状态机** |组件、表单、流或页面的可达状态和确定性转换的有界模型。|
|**查看** |页面或数据级表示，例如默认、加载、空或错误。它不能替代完整的状态机。|
|**活动** |请求转换的用户、系统、数据、时间或历史事件。|
|**守卫** |允许、拒绝或重定向转换的条件。|
|**效果** |由转换引起的工作，例如请求、存储更新、焦点移动、公告或导航。|
|**结果** |命名的成功、空、无效、失败、超时、取消或冲突结果及其下一个状态。|
|**异步策略** |待处理反馈、并发、重复事件、取消、超时、过时响应、重试、回滚和恢复的规则。|
|**焦点合约** |过渡期间的初始焦点、顺序、移动、恢复、可见性和公告行为。|
|**历史合约** |URL 路径/查询/哈希/存储以及推送/替换、后退/前进、刷新、深层链接、滚动和焦点恢复行为。|

## 运动和长滚动

|术语 |意义|
|--- |--- |
|**动作序列** |一组有目的的稳定状态，由声明的时间或进度规则组成。|
|**司机** |进度的来源，例如时间、文档滚动、容器滚动、拖动、媒体时间或状态转换。|
|**时间轴/轨道** |通过序列驱动的有序范围和属性更改。|
|**场景** |较长序列中有意义的稳定状态或间隔。|
|**粘性/固定区域** |内容保留在声明的包含边界内，同时布局空间、滚动所有权、焦点和回退保持定义。|
|**逆转/重新进入政策** |当进度向后移动、用户返回、输入快速变化或序列被中断时会发生什么。|
|**减少运动替代方案** |一种静态或更短的行为，可保留任务、内容、状态和焦点，同时消除有问题的移动、视差或循环。|
|**运动后备** |不支持驱动程序或目标能力时使用的语义结果；完成不能仅依赖于动画结束事件。|

## 无障碍

|术语 |意义|
|--- |--- |
|**辅助功能配置文件** |目标标准/版本/级别以及交付范围的语义、输入、视觉、媒体、动作、响应和 QA 要求。默认 Web 配置文件使用 WCAG 2.2 AA 级。|
|**一致性目标** |完整实施旨在满足该标准。它不是模型、独立组件、自动评分或未完成流程的一致性声明。|
|**可访问的名称/描述** |以编程方式公开的标签和元素的支持解释；可见文本、名称中的标签和重复控制上下文保持对齐。|
|**阅读顺序** |内容关系暴露的语义顺序，独立于纯粹的视觉布局。|
|**焦点订单** |键盘/辅助技术按可操作内容的顺序遍历。它必须保持逻辑性和可见性，并且可能只是故意与阅读顺序不同。|
|**实时状态** |宣布了一项有意义的动态更新，但没有意外地转移焦点。|
|**回流焊** |在所需的缩放和缩小等效宽度时保留内容和功能，而不会出现不合理的二维滚动。|
|**目标尺寸** |可操作指针区域，包括适用的 WCAG 例外和任何更强的产品/平台要求。|

## 能力和表现

|术语 |意义|
|--- |--- |
|**目标概况** |命名平台/运行时以及输入、输出、布局、媒体、网络、存储、内存和电源能力上下文。|
|**能力** |仅当声明支持或经过测试的替代方案时，合约才可以依赖的目标功能。|
|**基本经验** |即使视觉保真度或高级效果无法做到，内容、任务、媒体意义和结果也必须能够承受降级。|
|**后备** |用于无支持、未解决、失败或受限情况的计划安全替代方案。回退并不自动意味着偏差。|
|**降解** |在低带宽、离线、数据保护、低功耗、内存压力、缺少 API/编解码器或类似条件下有意过渡到减少但可用的体验。|
|**性能预算** |具有指标、单位、所有者、目标环境、测量点和证据的可测量限制。|
|**艺术指导** |保留媒体意义所需的裁剪、焦点/安全区域、方面、分辨率、格式、质量、海报/预览和来源选择。|
|**虚拟化门槛** |声明的数据量，之后渲染/窗口策略发生变化，同时标识、顺序、焦点、选择和可访问性保持正确。|

## 生命周期和治理

|术语 |意义|
|--- |--- |
|**生命周期** |从设计到合同、实施、QA、发布、运营、反馈的可追溯链。|
|**门** |包含范围、修订、证据、所有者和明确结果的设计、合同、实施、质量保证或发布决策。|
|**交接** |将已接受的来源和合同交付实施；这是生命周期的转变，而不是责任的终结。|
|**桥接就绪** |足够明确，以便受影响的门能够继续进行，而无需发明行为，也没有未跟踪的未知数。|
|**开放问题** |已知的 `unknown`、`unsupported` 或 `TBD` 决策，具有稳定 ID、确切范围、所有者、阻止状态、到期/审核点、安全回退、状态和最终决策链接。|
|**盲点** |版本化源/合同中不存在的相关含义或不确定性，仅存在于聊天、语音、记忆或未链接的任务中。“没有盲点”意味着没有未追踪的未知因素，并不是每个答案都是已知的。|
|**例外** |在实施之前记录的方法、来源或合同规则的批准例外依赖于它。|
|**偏差** |已接受的合同与实施或支持的目标之间故意的、经过审查的不匹配。它记录了要求、范围、差异、原因、影响、缓解、所有者、状态、证据和审查日期（如果适用）。|
|**缓解** |一种经过验证的措施，可减少异常或偏差对用户、可访问性、数据、安全/隐私、性能或维护的影响。|
|**可追溯性** |能够跨源、合同、实施、测试、问题、偏差和发布修订遵循稳定的需求或身份。|

## 验证和报告

|术语 |意义|
|--- |--- |
|**自动检查** |具有可重现的通过/失败结果的确定性测试。|
|**启发式检查** |一种识别可能风险并需要人类判断的工具发现。|
|**手动检查** |由合格人员进行语义、产品、视觉、可访问性或特定目标的审查。|
|**运行时检查** |在声明的实施环境中进行的测量或观察。|
|**验证器** |仅评估其声明的覆盖范围中所代表的规则的工具；干净的报告并不完整的 BRIDGE 或 WCAG 验证。|
|**严重性** |报告优先级 `error`、`warning` 或 `info`；它不会取代门状态。|
|**门状态** |`pass`、`pass with accepted deviations`、`blocked` 或针对审核范围的精确合理的 `not applicable` 决定。|

## 书写和命名

- 以规范英语保存机器可读的名称、标签值、id、引用、枚举值和 JSON 字段。
- 保持稳定的英文设计标识`kebab-case`；使用可见标签的本地化产品副本。
- 不要使用“断点”作为每个响应决策的简写，“状态”作为每个屏幕截图的简写，或“异常”作为每个差异的简写。
- 区分响应式转换、安全回退、源/合同异常和实施偏差。
- 区分设计装置和运行时数据以及 `bridgeKey` 和目标平台定位器。
- 区分移交、实施、QA、发布和资产导出：它们是不同的生命周期操作。
